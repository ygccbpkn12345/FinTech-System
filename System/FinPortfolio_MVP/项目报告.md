## 1. 项目定位与总体架构

### 1.1 项目目标

FinPortfolio 是一个**金融算法实验与回测平台**（研究工具，非实盘交易系统）。核心目标是把两篇论文算法以**独立插件**形式接入统一平台，实现：

- **算法可插拔**：新算法接入只需 `manifest.yaml`（声明）+ `adapter.py`（适配器），不改任何核心代码与前端；
- **环境隔离**：每个插件运行在自己的 Python 解释器与独立子进程中，TensorFlow / PyTorch 等重依赖互不污染、不进入后端进程；
- **论文代码零修改**：原始论文代码（`System/ASACPL`、`System/HMMP`）位于仓库之外，适配器以受控方式驱动；
- **口径诚实**：论文原始口径（`paper_original`，费前）与平台统一口径（`unified_rebalance`）严格分离，所有指标假设显式声明，不伪造、不混用。

### 1.3 关键设计决策

| 决策 | 说明 | 落点文件 |
|---|---|---|
| 注册与执行分离 | FastAPI 进程只读 manifest.yaml，绝不 import 插件代码 → TF/torch 不进后端进程 | `plugin_registry.py` |
| 独立 Python 环境 | 每个插件可在 manifest 声明 `python_executable`；缺失时回退后端解释器并警告 | `manifest_schema.py` / `plugin_registry.py` |
| 安全子进程 | 命令强制 `[python, runner, payload.json]` 参数列表，禁止 shell 拼接；Windows `CREATE_NEW_PROCESS_GROUP` + `taskkill /T /F` 兜底终止 | `task_manager.py` / `experiment_service.py` |
| 论文代码零修改 | ASACPL 用 importlib 复刻 `__main__` 流程（含 state_space 注入、硬编码日志目录预创建）；HMMP 用 CWD 注入 `Data/`（junction 优先）后以白名单 argv 调 `B_Train.py` | `plugins/asacpl/adapter.py` / `plugins/hmmp/adapter.py` |
| 统一结果契约 | StandardPortfolioResult：毛/净收益分离、权重关联真实代码、非负与预算约束强校验（容差 5e-3）、口径假设显式 | `result_schema.py` |
| 两种回测模式 | `paper_original`（论文原始口径，费前）与 `unified_rebalance`（平台统一再平衡口径）绝不混用 | `result_schema.py` / 各 adapter |

## 3. 后端架构详解

后端采用**分层架构**：`api`（路由，薄）→ `services`（编排）→ `core`（领域逻辑）+ `workers`（进程外执行）。组合根在 `main.py`，服务实例挂到 `app.state`，路由通过 `request.app.state.*` 取用（避免全局单例耦合，便于测试注入）。

### 3.1 `app/main.py` — 组合根（75 行）

**职责**：应用装配与服务生命周期。

| 关键步骤 | 代码位置 | 说明 |
|---|---|---|
| 建目录 | `ensure_runtime_dirs()` | 启动即创建 datasets/experiments/logs/checkpoints |
| CORS | `allow_origins=[localhost:5174/4173]` | 仅放行前端开发/预览端口 |
| 任务管理器 | `TaskManager(max_concurrent=env或1, default_timeout=86400)` | 并发上限可用 `FINPORTFOLIO_MAX_CONCURRENT_TASKS` 覆盖，默认超时 1 天 |
| 服务装配 | `ExperimentService(task_manager, dataset_service)` | 依赖注入 |
| 中断恢复 | `experiment_service.recover_interrupted()` | 把上次进程退出时 PENDING/RUNNING 的实验标记为 FAILED（error="backend restarted..."） |
| 状态挂载 | `app.state.tasks / datasets / experiments` | 路由层访问入口 |
| 路由挂载 | 6 个 router + `GET /api/health` | 见第 4 节 |
| 优雅关停 | `@atexit.register → task_manager.shutdown()` | 终止运行中子进程 |

### 3.2 `core/paths.py` — 路径解析（38 行）

集中定义所有存储位置，全部支持环境变量覆盖：

| 常量 | 环境变量 | 默认值 |
|---|---|---|
| `PROJECT_ROOT` | `FINPORTFOLIO_ROOT` | backend 的上级（项目根） |
| `PLUGINS_DIR` | `FINPORTFOLIO_PLUGINS_DIR` | `<ROOT>/plugins` |
| `DATASETS_DIR` | `FINPORTFOLIO_DATASETS_DIR` | `<ROOT>/datasets` |
| `EXPERIMENTS_DIR` | `FINPORTFOLIO_EXPERIMENTS_DIR` | `<ROOT>/experiments` |
| `LOGS_DIR` / `CHECKPOINTS_DIR` | 同前缀 | `<ROOT>/logs`、`<ROOT>/checkpoints` |
| `DEFAULT_ORIGINAL_CODE_ROOT` | `FINPORTFOLIO_ORIGINAL_CODE_ROOT` | 项目根的上级（`System/`） |
| `PLUGIN_RUNNER_PATH` / `PLUGIN_INTERFACE_PATH` | — | workers/plugin_runner.py、core/plugin_interface.py 的绝对路径（供子进程注入） |
| `DEFAULT_PYTHON` | — | `sys.executable`（插件未声明独立解释器时回退） |

### 3.3 `core/manifest_schema.py` — manifest 严格校验（Pydantic v2）

manifest 是算法元数据的**唯一可信来源**（后端不执行插件代码，只能信声明），因此校验极严：所有模型 `extra="forbid"`（未知字段直接拒绝）。

**模型层级**：

```
PluginManifest
├─ schema_version: "1.0"（固定）
├─ id: 匹配 ^[a-z][a-z0-9_]{1,63}$
├─ name / version / description
├─ paper: PaperInfo（title 必填；authors/venue/year/url/note 可选）
├─ framework: str（tensorflow / pytorch / numpy...）
├─ python_executable: Optional[str]（插件独立 venv；空=共用后端解释器）
├─ capabilities: list[str] ⊆ KNOWN_CAPABILITIES，禁重复
├─ dataset_requirements: list[DatasetRequirement]（至少 1 条）
├─ parameters: list[ParameterSpec]
├─ outputs: OutputSpec（result_format 固定 "StandardPortfolioResult"）
└─ execution: ExecutionSpec
    ├─ adapter_file（默认 "adapter.py"，相对插件目录）
    ├─ original_code_subdir（论文代码目录，相对 ORIGINAL_CODE_ROOT 或绝对路径）
    ├─ default_timeout_seconds（默认 86400，≤ max）
    └─ max_timeout_seconds（默认 604800）
```

**受控词表**：

- `KNOWN_CAPABILITIES = train / predict / backtest / stock_selection / industry_allocation / news_analysis / portfolio_weights`
- `KNOWN_MODALITIES = prices / covariance / tech_indicators / stock_features / industry_prices / industry_news / news`

**ParameterSpec 校验规则**（前端表单与后端校验共用这套声明）：

- `name` 必须是合法标识符；`type ∈ {int, float, str, bool, enum}`；
- enum 必须给 `choices` 且 default ∈ choices；
- 数值型必须有数值 default，且 min ≤ default ≤ max；int 型 default 必须整数；
- bool 型 default 必须 bool；str 型必须有 default；
- `cli_flag` 字段供子进程适配器把参数映射为命令行旗标（HMMP 使用）；
- 可选 `advanced`（前端折叠高级参数）、`required`（必填校验）。

**辅助方法**：`parameter_by_name(name)`、`default_params()` → `{name: default}` 字典。

### 3.4 `core/plugin_interface.py` — 插件抽象基类（纯 stdlib，117 行）

**关键约束**：本文件**只允许标准库**（不能 import fastapi/pandas/numpy），因为它会被 plugin_runner.py 用 importlib 注入到插件自己的解释器（可能是 TF/PyTorch 独立 venv）中。

**`BasePortfolioPlugin` 提供的接口**：

| 方法 | 作用 | 默认行为 |
|---|---|---|
| `__init__(context)` | context 由 runner 注入：experiment_id / 数据集路径 / work_dir / manifest 摘要 | 存为 `self.context` |
| `get_info()` | 返回 manifest 摘要 | 从 context 取 |
| `get_config_schema()` | 返回参数声明 | 从 context.manifest.parameters 取 |
| `validate_dataset(dataset)` | 数据集校验（返回问题列表） | 按 manifest 的模态要求检查 |
| `train / predict / backtest / stock_selection(params, context)` | 能力方法 | 未实现则抛 `PluginCapabilityError`（任务标 FAILED，保留准确错误） |
| `normalize_result(raw, context)` | 原始输出→标准结果 | 默认要求能力方法直接返回标准 dict |
| `supports(capability)` | 能力探测 | capabilities 元组声明 + 方法是否被真实覆盖双重判断 |

**适配器约定（鸭子类型即可，不强制继承）**：adapter.py 必须暴露 `class Adapter`，构造函数接受 payload dict，能力同名方法 `(params: dict, context: dict) -> dict`，返回 dict 必须符合 StandardPortfolioResult 结构。

### 3.5 `core/plugin_registry.py` — 插件注册表（273 行）

**模块级单例**：`registry = PluginRegistry(); registry.reload()`——导入即扫描。

| 接口 | 作用 |
|---|---|
| `reload()` | 重扫 plugins 目录：遍历子目录（跳过 `_`/`.` 开头），逐个 `_load_one`；单个失败只记入 `_load_errors`，不影响其他插件；插件 id 重复也视为错误。返回扫描摘要 `{registered, failed, total_scanned}` |
| `_load_one(plugin_dir)` | 读 manifest.yaml → `yaml.safe_load` → `PluginManifest(**raw)` 严格校验；检查 adapter 文件存在（只查不执行）；解析 `python_executable`（路径不存在→警告并回退后端解释器）；检查论文原始代码目录存在（缺失→警告） |
| `list_plugins(detail)` | 输出全部插件摘要（含失败条目的 ERROR 占位），按 id 排序 |
| `get(algorithm_id)` | 取已注册插件，未注册抛 KeyError |
| `validate_params(algorithm_id, params)` | **参数校验合并**：未知参数拒绝；按 ParameterSpec 做类型强转（int/float/bool/enum/str）与 min/max 越界拒绝；required 参数必须有值；返回「默认值+用户覆盖」合并后的完整参数 |
| `scan_summary()` | 注册表摘要（供 /api/system/overview） |

**错误隔离设计**：任何插件 manifest 非法（YAML 语法错、Pydantic 校验失败、adapter 缺失）都被捕获为该插件自身的 ERROR 状态，注册表与其余插件继续工作。

### 3.6 `core/result_schema.py` — 统一结果契约（179 行）

`StandardPortfolioResult` 是**所有**实验结果（插件执行、CSV 导入）的唯一落盘格式，Pydantic 强校验：

**字段分组**：

| 组 | 字段 | 说明 |
|---|---|---|
| 标识 | experiment_id / algorithm_id / algorithm_version / dataset_id / dataset_version / configuration | 运行溯源 |
| 协议 | `backtest_mode` ∈ {paper_original, unified_rebalance}、trading_protocol（自由 dict：执行时点/费率/再平衡频率等） | **前端必须展示**的口径元信息 |
| 序列 | dates、`daily_returns`（毛）、`net_daily_returns`（扣费，可空）、portfolio_values、turnover | 长度必须全部等于 dates |
| 权重 | `stock_weights: list[dict[ticker, w]]`、cash_weights、industry_weights（可空） | 每期 dict 关联真实代码 |
| 指标 | metrics（自由 dict）+ `metric_assumptions`（252 交易日 / rf / compound / simple） | 口径假设显式 |
| 附件 | artifacts（name/path/kind）、stock_selection（可空的筛选快照） | |
| 诚实标注 | `cost_included`（算法原始输出是否已含费）、notes、`asset_label_mode` ∈ {ticker, position_index}、`weights_available`、execution_status 固定 SUCCEEDED |

**校验规则**（`_check_series` / `_check_weights`）：

1. 各序列长度与 dates 一致；dates 严格升序且唯一；
2. `daily_returns[i] > -1`（简单收益不得 ≤ -100%）；
3. **净值一致性**：portfolio_values 必须严格等于毛收益累乘或扣费收益累乘（从 1.0 起，rel_tol=1e-6）——防止伪造净值；
4. 权重约束（`weights_available=True` 时）：标签非空、权重非负（容差 -1e-6）、每期 `sum(股票)+cash ≈ 1`（容差 `BudgetTolerance=5e-3`，因 HMMP 权重按 4 位小数导出）；industry_weights 同样做预算校验；
5. `weights_available=False`（纯收益导入）时跳过权重校验，且要求权重全空。

`validate_result_dict(data)` 是唯一入口：runner 输出 / 导入构造的结果都经它变成强校验对象。

### 3.7 `core/metrics.py` — 指标计算（114 行，仅依赖 numpy）

计算口径全部显式（文件头注释即文档）：

| 指标 | 公式 |
|---|---|
| 累计收益 | `wealth[-1] - 1`，wealth = cumprod(1+r) |
| 年化收益（几何复利） | `wealth[-1] ** (252/n) - 1` |
| 年化波动 | `std(r, ddof=1) * sqrt(252)` |
| Sharpe | `(mean(r) - rf/252) / std(r) * sqrt(252)`，rf 默认 0；零波动序列（std<1e-12）返回 None 而非 inf |
| Sortino | 分母仅用下行波动（低于 rf 的部分） |
| Max Drawdown | wealth / running_max - 1 的最小值 |
| Calmar | 年化收益 / \|MDD\| |
| 换手（单边） | `mean(0.5 * sum|w_t - w_{t-1}|)` |

**可注入性**：本模块只依赖 numpy，plugin_runner 会把它以 `finportfolio_metrics` 模块名注入插件子进程，供各 adapter 复用同一口径。

辅助函数：`turnover_series(stock_weights, cash_weights)`（首日按 100% 现金建仓计 0.5×投资比例）、`wealth_series`、`drawdown_series`。

### 3.8 `database/json_store.py` — JSON 持久化（50 行）

极简键值存储：`read / write / update(fn)`，线程锁 + 临时文件 `os.replace` 原子替换（Windows 友好，无外部数据库依赖）。当前主要服务于需要原子读-改-写的场景；数据集索引与实验元信息各自直接读写 JSON 文件。

### 3.9 `workers/task_manager.py` — 子进程任务管理器（309 行）

**职责**：把「长时间算法训练」与「FastAPI 请求线程」解耦。

**Task 数据类**：task_id、command（**argv 列表，绝不 shell 字符串**）、cwd、log_path、timeout_seconds、env、state、returncode、error、三个时间戳、process 句柄、cancel_requested。

**状态机**：`PENDING → RUNNING → SUCCEEDED / FAILED / CANCELLED`（TERMINAL 三态）。

| 组件 | 机制 |
|---|---|
| 工作线程池 | `max_concurrent` 个 daemon 线程消费 `queue.Queue`；默认并发 1（可用环境变量调） |
| 超时线程 | 每 2s 扫描 RUNNING 任务，超时则 `_terminate` + 标 FAILED |
| 进程启动 | `subprocess.Popen(command, shell=False)`，stdout/stderr 合流追加写日志文件；env 强制 `PYTHONIOENCODING=utf-8`、`PYTHONUNBUFFERED=1`；Windows 加 `CREATE_NEW_PROCESS_GROUP` |
| 日志 | 每次运行写入起止分隔头（task id / command / cwd / 时间戳 / exit code） |
| 取消 | PENDING 直接取消；RUNNING 先 `terminate()`，失败则 Windows `taskkill /PID <pid> /T /F` 杀整棵进程树（TF/MAPPO 会 spawn 子进程，必须杀树），再兜底 `kill()`；最多等 15s 落定 |
| 完成回调 | `on_finish(task)` 钩子供 ExperimentService 挂接结果校验（回调异常不影响任务状态） |
| 查询 | `status / logs(tail) / list_tasks(state) / running_count` |
| 关停 | `shutdown()`：停止派发 + 取消所有 RUNNING |

### 3.10 `workers/plugin_runner.py` — 插件执行器（141 行，纯 stdlib）

**调用方式**：`python plugin_runner.py <payload.json>`（由 TaskManager 以 `[插件解释器, runner路径, payload路径]` 启动）。

**payload.json 结构**（由 ExperimentService 生成）：

```json
{
  "experiment_id": "exp_xxx",
  "plugin_dir": "...",            // 插件目录（也是子进程 cwd）
  "adapter_file": "adapter.py",
  "capability": "train",          // 要调用的能力
  "params": {...},                // 已按 manifest 校验合并的参数
  "work_dir": "...",              // 插件专属可写工作目录
  "output_dir": "...",            // result.json 写入目录（实验目录）
  "dataset": {...},               // 数据集元信息（id/name/market/storage_path/files/modalities/date_range/assets）
  "manifest": {...}               // manifest 完整摘要
}
```

**执行流程**（退出码语义：0 成功 / 2 参数或文件错误 / 3 适配器加载失败 / 4 能力执行失败）：

1. 读 payload；
2. importlib 注入两个跨环境模块：`plugin_interface.py` → `finportfolio_plugin_interface`，`metrics.py` → `finportfolio_metrics`（注入失败仅警告，adapter 可鸭子类型工作）；
3. `sys.path.insert(0, plugin_dir)` 后 importlib 加载 adapter.py → 必须有 `class Adapter`；
4. `Adapter(payload)` 实例化 → 调用与 capability 同名的方法 `method(params, payload)`；
5. 返回必须是 dict → 补默认字段（experiment_id / algorithm_id / version / dataset_id / configuration ← params）；
6. 写 `<output_dir>/result.json`；后端在任务完成后用 Pydantic 严格校验该文件。

### 3.11 `services/dataset_service.py` — 数据集服务（330 行）

**设计理念**：统一的是数据集「元信息与接口协议」，**不统一**数据格式——每个算法保留自己的加载与预处理（ASACPL 的 CNN 张量、HMMP 的多模态特征互不强求一致）。

**两种存储模式**：

- `reference`：登记本机已有研究数据目录（不复制，研究数据量大）；`storage_path` 指向原目录；
- `copy`：复制到 `datasets/storage/<dataset_id>/` 受管存储（带 Windows 杀软占用重试，最多 5 次）。

| 接口 | 作用 |
|---|---|
| `register(...)` | 登记：files 为「逻辑名→相对路径」映射；自动探测日期列/代码列（候选名 date/Date/datetime/time/timestamp、tic/ticker/symbol/StockCode/code），解析出 assets 列表、date_range、feature_schema；dataset_id 由名称派生，冲突自动加后缀 `_2` `_3` |
| `list / get / delete` | 索引读写（datasets/index.json） |
| `file_path(dataset_id, logical)` | 逻辑名 → 绝对路径（adapter 据此读数据） |
| `validate(dataset_id)` | 完整性检查：文件存在、CSV 可读、日期列有效（invalid_dates 计数）、模态已声明 → `{valid, problems, file_reports}` |
| `check_compatibility(plugin, dataset_id)` | **算法-数据集兼容性**：manifest 的某条 dataset_requirements 的 modalities ⊆ 数据集 available_modalities 即兼容（多条要求满足其一）；市场不匹配、字段未能验证、日期范围未知 → warnings；不修改任何一方 |
| `compatible_datasets(plugin)` | 枚举全部数据集的兼容性（供前端下拉过滤） |

### 3.12 `services/experiment_service.py` — 实验编排（307 行）

**一次实验 = 一个算法能力在一份数据集上的一次真实执行**（或一次导入，kind=import）。

`create_experiment(body)` 的完整编排链：

```
1. registry.get(algorithm_id)              → 插件必须 READY
2. capability ∈ manifest.capabilities      → 且 ∈ CAPABILITY_RUNNABLE(train/predict/backtest/stock_selection)
3. ds.get(dataset_id)                      → 数据集必须存在
4. ds.check_compatibility(...)             → 不兼容直接拒绝
5. registry.validate_params(...)           → 参数合并+强校验
6. 生成 experiment_id = exp_<uuid12>，建实验目录与 work/
7. 写 payload.json（见 3.10）
8. command = [plugin.python_executable, PLUGIN_RUNNER_PATH, payload_path]  ← 安全 argv
9. 写 meta.json（status=PENDING，notes 继承插件警告）
10. tm.submit(task_id=experiment_id, ...)   → 入队，worker 线程择机执行
```

**`_on_task_finish(task)` 回调**（TaskManager worker 线程调用）：

- FAILED → error 写入 meta；
- SUCCEEDED → 读 `result.json`：缺失 → 状态改 FAILED（"no result.json produced"）；存在 → `validate_result_dict` 严格校验 → 失败则 FAILED 并保留 pydantic 错误；成功则把 `backtest_mode`、`result_summary`（10 项关键指标）、`artifacts`、`notes` 回写 meta.json。

其他接口：`list_experiments`（扫 `*/meta.json`，按创建时间倒序）、`get_experiment(detail)`、`get_result`（重读+重校验 result.json）、`delete_experiment`（运行中先取消再删目录）、`recover_interrupted`（启动时把遗留 PENDING/RUNNING 标 FAILED）。

### 3.13 `services/import_service.py` — 论文 CSV 导入（301 行）

把论文代码直接产出的 CSV（不跑模型）转成 StandardPortfolioResult，**回测模式固定 `paper_original`**。

**已核实的原代码口径**（写在文件头，不得虚构）：

- ASACPL `env_new.py step()`：`portfolio_return = Σ((close_t/close_{t-1} - 1) * w)`，transaction_cost_pct 仅存储未参与计算 → `cost_included=False`；
- HMMP `B_PortfolioEnv.py`：无交易费用项 → `cost_included=False`。

**处理管线**：

| 函数 | 作用 |
|---|---|
| `returns_frame(df)` | 归一化收益表：识别日期列（date/datetime/time/timestamp）与收益列（return/daily_return/daily_returns/portfolio_return）；拒绝空表/重复日期/收益 ≤ -100% |
| `_asacpl_weights(df)` | 解析 ASACPL `04_a3c_test_weights_CNN.csv`（date + actions 序列化列表）→ `Asset_N` 位置标签，`asset_label_mode=position_index` + notes 提示需 ticker 顺序映射 |
| `_hmmp_compose(industry_df, intra_df)` | **HMMP 最终权重组合**（任务书第八节）：`股票最终权重 = 行业资金权重 × 行业内条件权重`；CASH 列 → cash_weights；无明细时允许仅行业层 |
| `import_result(...)` | 主入口：对齐长度（权重与收益行数不一致时截断并记 notes）→ 计算 turnover/values/metrics → 构造并通过 `validate_result_dict` → 落盘 result.json + meta.json（kind=import, status=SUCCEEDED） |

导入结果与真实执行结果在存储层完全同构，前端无需区分渲染。

## 5. 插件子系统详解

### 5.1 插件接入契约

**一个插件 = 一个目录**，包含：

1. `manifest.yaml` — 声明（id/能力/参数/数据要求/执行配置），经 PluginManifest 严格校验；
2. `adapter.py` — 实现，暴露 `class Adapter`，按能力实现 `train/predict/backtest/stock_selection(...)` 等方法，返回 StandardPortfolioResult dict。

**执行链**（注册与执行彻底分离）：

```
后端进程                          插件子进程（可用独立 venv）
─────────                        ──────────────────────────
PluginRegistry.reload()
  仅解析 manifest.yaml
        │
ExperimentService.create_experiment()
  兼容性检查 + 参数校验
  写 payload.json
        │
TaskManager.submit()
  [python_exe, plugin_runner.py, payload.json]
        ├──────────────────────▶  plugin_runner.main()
                                  ├ 注入 plugin_interface / metrics（importlib）
                                  ├ 加载 adapter.py → Adapter(payload)
                                  ├ method(params, payload)
                                  └ 写 result.json
        ◀───────────────────────  exit 0
_on_task_finish()
  validate_result_dict(result.json)
  回写 meta.json
```

### 5.2 `plugins/equal_weight/` — 基线插件（验收示例）

| 项 | 内容 |
|---|---|
| manifest | id=`equal_weight`，framework=numpy+pandas，capabilities=[backtest, portfolio_weights]，数据要求：任意市场 + prices 模态（date/tic/close）；参数：`top_k`（0=全股票，>0 按代码字典序取前 K，规则显式声明）、`cost_pct`（单边费率 0~0.01）、`initial_cash_ratio`（0~0.5）；超时 600s |
| adapter | `backtest()`：加载长表行情 → pivot 宽表（剔全空列、ffill 停牌）→ 每日再平衡至 `(1-cash)/N` 等权；毛收益=等权平均×权益比；**换手=目标权重 vs 漂移后权重的单边差额**；`cost_pct>0` 时输出 net 序列并在 net 上算指标；导出 weights.csv 工件 |
| 口径 | `backtest_mode=unified_rebalance`，trading_protocol 完整记录执行时点/频率/费率模型/股票池规则 |
| 意义 | **插件化架构的验收示例**——接入时未改任何核心代码与前端；只依赖 NumPy，可随时验证平台链路 |

**真实验证结果**（S&P500 2023 · 20 只股票 · 每日再平衡 · cost_pct=0.001）：250 个交易日，累计 +26.24%，几何年化 +26.48%，Sharpe 2.13（rf=0），MDD -7.59%，平均单边换手 0.86%/日；毛/净收益分离，权重约束全部通过。

### 5.3 `plugins/asacpl/` — 论文 A（TensorFlow / A3C）

**算法**：Stable Sequential Portfolio Learning via Asset Space Compression and State Representation —— HLB-AS 直方图引导叶子生长筛选候选股票 + CNN 时序特征/协方差状态表示 + 异步 Actor-Critic（A3C）组合权重优化。

**适配策略（论文代码零修改）**：

1. `_stage_dataset()`：把数据集的 02_train_CNN.csv / 02_test_CNN.csv 复制到实验 `work/datasets/`；
2. `_load_original_module()`：importlib 以模块方式加载 `System/ASACPL/04_CNNAndA3C.py`（`__main__` 块不执行）；
3. `train()` 复刻论文 `__main__` 流程：环境参数**原值**（hmax=500, initial_amount=1000000, transaction_cost_pct=0.001, reward_scaling=0, tech_indicator_list=[f1..f4]），按数据实际股票数注入 `state_space/stock_dim/action_space/initial_weights`，并给模块注入 `mod.state_space`（DRL_prediction 引用）；
4. **硬编码日志目录预创建**：论文 WorkerAgent 会向作者机器绝对路径追加 loss/reward CSV，适配器只 `os.makedirs` 确保其存在，不改行为；
5. 训练后在同一进程内按论文协议评估（原代码不保存模型权重 → 不提供独立 predict）→ 输出 3 个 CSV 工件；
6. `_normalize()`：收益表归一化；**actions 权重按当日 (date,tic 排序) 对齐真实股票代码**；`_parse_actions()` 兼容论文导出的两种形态（首行 Python list repr 可 ast 解析；其后 numpy 数组 str() 空格分隔且可能折行 → 正则提取浮点数兜底，解析失败必须报错禁止静默置空）；无法对齐时回退 `Asset_N` + `asset_label_mode=position_index`。

**诚实标注**：`cost_included=False` + notes 说明「原 env 存储 transaction_cost_pct=0.001 但 step() 未扣费，收益为毛收益」。

**manifest 要点**：capabilities=[train, portfolio_weights]；数据要求 SSE50/SP500 + prices/covariance/tech_indicators（f1-f4、cov_list）；参数 max_episodes（默认 100 为演示值）、num_workers；`original_code_subdir: ASACPL`；超时 86400s。

### 5.4 `plugins/hmmp/` — 论文 B（PyTorch / MAPPO）

**算法**：Hierarchical Multimodal Portfolio Learning for Joint Stock Selection and Industry Allocation —— 行情/行业价格/金融新闻多模态表示 + Sparse MoE + 行业 Top-K 与行业内股票 Top-K 分层选择 + CTDE-MAPPO。

**适配策略（CWD 注入 + 白名单 argv）**——利用 `B_Train.py` 自带完整 argparse CLI 且数据从 CWD 相对路径 `Data/` 读取、结果写 `Results/` 的特性：

1. `_stage_data_dir()`：在工作目录构造 `Data/`（Windows 优先 `mklink /J` 目录联接，失败回退 copytree）——大数据集零拷贝；
2. `_build_argv()`：**只传 manifest 声明了 `cli_flag` 的参数**（device/split_mode/epochs/industry_top_k/intra_top_k/max_cash_weight/seed）+ `--run_name`，白名单之外的参数一律不传递；
3. `train()`：以 `[sys.executable, B_Train.py, *argv]` 参数列表 subprocess 运行（无 shell），stdout/stderr 透传（由 TaskManager 统一落盘 run.log）；退出码非 0 → RuntimeError；
4. `_normalize()`：从 `Results/<run_name>/` 读取 3 个论文输出（缺失报错）→ **最终权重 = 行业资金权重 × 行业内条件权重**，CASH 列 → cash_weights（与 import_service 同一组合口径）；`best_model_window_0.pt` 存在时登记为 checkpoint 工件。

**manifest 要点**：capabilities=[train, portfolio_weights, industry_allocation, news_analysis]；数据要求 CSI500 + stock_features/industry_prices/industry_news；7 个参数全部带 cli_flag（enum: device=cpu/cuda、split_mode=fixed/walk_forward；int: epochs/industry_top_k/intra_top_k/seed；float: max_cash_weight）；`original_code_subdir: HMMP`。

**诚实标注**：notes 说明论文 env 不扣费、权重按 4 位小数导出（对应结果契约 5e-3 预算容差）。

### 11.2 已知限制

- ASACPL/HMMP 完整论文级训练（数千 episode/epoch）在 CPU 上耗时极长；适配层与任务通道已用真实数据/代码打通。
- 两个论文插件当前 `python_executable: null`（回退后端解释器并警告）；需独立 TF/torch 环境时改 manifest 指向对应 venv。
- 结果对比页对跨论文比较（ASACPL vs HMMP）始终提示「非受控公平基准」（市场/切分/协议不同）。
- 前端 hash 路由为自写实现（避免新增依赖）。
- ASACPL 原始脚本不保存模型权重（训练与评估同进程），故无独立 predict 能力；HLB-AS 筛选在论文 notebook 层，输入数据即筛选后产物，故不声明 stock_selection 能力。

### 11.3 工程亮点小结

1. **进程级隔离的插件架构**：注册（读 manifest）与执行（子进程 + 独立解释器）彻底分离，重依赖框架永不污染后端；
2. **契约驱动的前端**：算法、参数、能力、数据集全部运行时发现，新算法零前端发版；
3. **可审计的口径治理**：两种回测模式、毛/净收益分离、指标假设随结果落盘、对比页口径警告——研究诚信内建到数据契约里；
4. **工程化细节**：Windows 进程树击杀、junction 数据注入、原子写、服务重启恢复、坏插件隔离、导入文件溯源副本。
