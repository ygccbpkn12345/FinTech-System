# AnalystVerse 聊天工具路由与 DeepSeek 风格 UI 设计

## 目标

将当前以股票分析工作台为首页的应用改造成以自然语言聊天为入口的单机智能工具平台。用户可进行普通对话；当话题涉及股票预测或行情数据更新时，后端自动选择相应工具、补齐参数、执行现有能力，并在聊天中展示摘要和图表。原股票工作台继续承担完整分析详情展示。

该设计同时为后续接入以 HTTP 请求为主的其他项目预留稳定扩展点，新增能力时不改聊天编排主流程，也不要求聊天前端理解外部项目的私有协议。

## 范围

本期包含：

- DeepSeek 网页版风格的聊天首页与会话侧栏。
- 普通多轮聊天。
- 大模型意图判断、关键词兜底和工具选择。
- 缺失参数的多轮追问与上下文补全。
- 将现有股票预测流程封装成工具。
- 将现有行情爬取流程封装成工具。
- 股票预测摘要、关键指标和走势图在聊天消息内展示。
- 从摘要卡进入原股票分析工作台查看完整结果。
- 可注册本地工具和 HTTP 工具的统一扩展接口。
- 浏览器本地会话历史。

本期不包含：

- 登录、鉴权、权限、租户或用户管理。
- 数据库及服务端长期会话持久化。
- 独立网关或微服务拆分。
- 允许用户在聊天中指定任意 HTTP URL。
- 重启后恢复正在运行的任务。

## 视觉与交互

采用已确认的布局 A：DeepSeek 原生感布局。

- 左侧窄侧栏展示品牌、新对话、历史会话和设置入口，可折叠。
- 主区为最大宽度约 800px 的单列聊天流。
- 空白会话显示欢迎语、示例问题和底部圆角输入框。
- 用户消息靠右显示为轻量气泡；助手消息使用无气泡正文布局。
- 工具执行过程以紧凑状态行呈现，详细步骤默认折叠。
- 股票结果以内嵌卡片展示结论、置信度、风险摘要、关键指标和 ECharts 价格走势。
- 结果卡提供“查看完整分析”按钮，跳转至 `/dashboard` 并加载同一份结果，不重复计算。
- 移动端隐藏侧栏，消息、卡片和图表改为单列。
- 仅参考 DeepSeek 的空间布局和交互层级，不复制其品牌、Logo 或专有文案。

## 总体架构

### 前端

新增 `/chat` 路由并将根路径默认跳转到该页面。原 `/dashboard`、`/history`、`/reflection` 和 `/settings` 继续存在。

聊天前端只依赖统一消息协议，负责：

- 维护当前会话和浏览器本地历史。
- 发送消息并展示助手回复。
- 展示参数追问、工具状态、错误和结果卡。
- 根据标准 `visualizations` 描述渲染图表。
- 根据标准 `actions` 执行重试或站内跳转。

### 后端

FastAPI 内新增聊天编排层和 `POST /api/chat/messages` 接口。编排层负责：

1. 读取当前会话上下文。
2. 调用 DeepSeek 生成普通回复或结构化工具调用意图。
3. 当模型调用失败或结果不合法时，使用关键词规则兜底。
4. 通过工具注册表找到工具并校验参数。
5. 参数不足时返回追问消息，并在会话状态中保存待执行工具和已有参数。
6. 参数齐全时执行工具，将私有返回值转换为统一工具结果。

服务端会话只保存在当前 FastAPI 进程内。应用为单机部署并保持单 worker，这与现有分析任务和 SSE 状态的运行方式一致。

## 工具模型

每个工具实现统一契约：

```python
class Tool(Protocol):
    name: str
    description: str
    required_parameters: tuple[str, ...]

    def validate(self, arguments: dict) -> list[str]: ...
    def execute(self, arguments: dict, context: ToolContext) -> ToolResult: ...
```

`ToolResult` 是后端内部标准返回对象：

```json
{
  "tool": "stock_prediction",
  "status": "completed",
  "summary": "综合判断为……",
  "data": {},
  "visualizations": [],
  "actions": []
}
```

注册表支持两种实现：

- `local`：直接调用当前 FastAPI 项目内的 Python 服务。
- `http`：由服务端静态配置 URL、方法、请求映射、超时和响应适配器，再调用其他项目。

HTTP 地址不得从用户消息或模型参数中取得，防止意外访问任意本地或远程地址。当前单机版本不引入鉴权和运维控制台。

## 首批工具

### `general_chat`

当不需要业务工具时，由 DeepSeek 返回正常聊天文本。该能力不进入业务工具注册表的执行路径，但在统一消息协议中表现为 `text` 消息。

### `market_data_crawler`

把当前 `/api/data/fetch` 中的抓取逻辑下沉为可复用服务，并由 API 与聊天工具共同调用。参数包括股票代码、起止日期和数据源。工具结果保留 `ok`、`partial`、`error` 状态，并列出各数据模块的成功或失败信息。

聊天编排器不会在数据缺失时擅自开始耗时爬取，而是先返回确认动作。用户确认后才执行爬虫工具。

### `stock_prediction`

复用现有分析任务创建、状态查询、SSE 事件和结果组装流程。必填参数为股票代码与分析日期。

如果用户只说“预测中兴通讯”，系统先解析股票实体，再追问分析日期。用户下一轮给出日期后，编排器从待执行状态中补齐股票代码并启动预测。

完成后工具结果包含：

- 决策摘要、动作和置信度。
- 风险摘要。
- 股票基本信息与关键指标。
- 价格走势可视化描述。
- 指向 `/dashboard` 的完整分析动作，携带任务 ID 或已保存结果引用。

## 消息协议

聊天接口请求：

```json
{
  "conversationId": "optional-existing-id",
  "message": "预测中兴通讯",
  "clientMessageId": "uuid"
}
```

聊天接口响应：

```json
{
  "conversationId": "uuid",
  "messages": [
    {
      "id": "uuid",
      "role": "assistant",
      "type": "parameter_request",
      "content": "希望分析哪个交易日？",
      "tool": "stock_prediction",
      "missingParameters": ["analysisDate"]
    }
  ]
}
```

消息类型固定为：

- `text`：普通文本。
- `parameter_request`：请求缺失参数。
- `confirmation`：需要用户确认后执行的动作，例如爬取数据。
- `tool_progress`：工具正在执行或排队。
- `result`：工具执行完成后的标准结果。
- `error`：可展示、可重试的失败信息。

股票分析为长任务。聊天接口启动工具后立即返回 `tool_progress` 和任务 ID；前端复用现有分析 SSE 与结果接口更新该消息，避免新增第二套进度协议。

## 数据流

### 普通聊天

用户消息 → 聊天接口 → DeepSeek 判断无需工具 → 文本回复 → 聊天消息流。

### 缺参预测

用户消息 → DeepSeek 选择股票预测并提取股票 → 工具校验发现缺少日期 → 返回参数追问 → 用户补充日期 → 合并待执行参数 → 创建现有分析任务 → SSE 更新进度 → 获取结果 → 标准结果卡。

### 数据不足

股票预测校验发现数据不足 → 返回爬虫确认消息 → 用户确认 → 爬虫工具抓取并返回模块状态 → 数据完整则继续待执行预测；仍不完整则返回明确错误和失败模块。

### 未来 HTTP 项目

用户消息 → DeepSeek 根据工具描述选择工具 → 参数校验/追问 → HTTP 工具构建固定目标请求 → 响应适配器转换为 `ToolResult` → 通用结果渲染器展示文本、指标、图表和动作。

## 会话状态

服务端每个会话保存：

- 最近的用户与助手文本，用于正常多轮聊天。
- 待执行工具名称。
- 已收集的工具参数。
- 待确认动作。
- 当前业务任务 ID。

状态有数量上限和最近使用时间；超过上限或过期时清理。浏览器使用 `localStorage` 保存会话标题、消息和更新时间，用于刷新后恢复界面。敏感密钥和运行时模型配置不进入聊天消息或浏览器存储。

## 错误处理

- DeepSeek 意图路由失败或返回非法结构：使用关键词路由兜底。
- 普通聊天模型调用失败：返回 `error` 消息和重试动作。
- 参数不足：仅追问缺失字段，保留已识别字段。
- 参数无效：说明合法格式并继续等待该字段。
- 爬虫部分成功：返回 `partial`，列出成功与失败模块，不伪装为完全成功。
- 股票分析失败：沿用现有任务错误详情，并提供重试动作。
- HTTP 工具超时、非 2xx 或响应格式错误：适配成统一错误消息；不泄露堆栈。
- 浏览器刷新：从本地恢复已完成消息；运行中任务根据任务 ID 重新订阅或查询现有状态。

## 测试策略

后端测试覆盖：

- 工具注册、重复名称和未知工具。
- 大模型路由、非法结果及关键词兜底。
- 股票名称/代码识别、缺参追问和多轮补参。
- 爬虫确认与现有数据服务复用。
- 股票预测任务启动及标准结果映射。
- HTTP 工具请求映射、超时、非 2xx 和响应适配。
- 会话过期与上限清理。
- 聊天 API 请求/响应契约。

前端测试覆盖：

- 消息状态归并与本地持久化。
- 不同消息类型的渲染选择。
- 参数追问的连续对话。
- 股票结果数据到图表配置的转换。
- “查看完整分析”携带正确任务引用跳转。
- 工具失败后的重试。

端到端手工验收场景：

1. 普通问候得到正常回复。
2. “预测中兴通讯”会追问日期。
3. 补充日期后开始分析，并在聊天内显示进度和结果图。
4. 点击完整分析进入原工作台且不重复执行。
5. 数据缺失时先请求爬虫确认。
6. 确认后爬虫返回模块状态，并在可分析时继续预测。
7. 注册一个模拟 HTTP 工具后，无需修改聊天页即可显示其标准结果。

## 部署约束

- 保持当前 React + Vite、FastAPI、Nginx 单镜像部署方式。
- 保持一个 Uvicorn worker，以兼容进程内聊天会话、分析任务和 SSE 状态。
- 沿用现有 DeepSeek 配置与加密存储，不新增浏览器端密钥。
- 不引入数据库、消息队列或独立服务。
