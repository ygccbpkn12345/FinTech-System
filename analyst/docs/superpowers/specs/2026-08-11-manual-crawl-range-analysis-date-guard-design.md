# 手动爬取时间与分析日期前置校验设计

日期：2026-08-11

## 目标

用户在系统配置的爬虫区域手动选择开始日期和结束日期。行情与新闻只获取该区间的数据；基本面获取截止结束日期已公开的历史财报。智能分析启动前必须确认分析日期存在于本地可用交易日期中，日期不存在时只显示提醒，不创建任务、不切换到运行态，也不展示分析运行页面。

## 交互

爬虫模式显示必填的开始日期和结束日期，默认值为最近一年至当天。开始日期不得晚于结束日期，结束日期不得晚于当天。提交取数请求时发送 `startDate` 和 `endDate`。

抓取完成后仍跳转智能分析页并选择本次行情的最新交易日；如果区间内没有交易日，抓取接口返回错误，不跳转。

点击“开始分析”时，前端先请求该股票的可用日期列表并检查当前分析日期。日期不存在时显示一次警告并立即返回，保持欢迎/已有结果界面，不设置 loading、hasStarted、taskStatus、步骤或流状态。股票数据不完整时沿用同样的仅提醒行为。

## 后端协议

`POST /api/data/fetch` 接受：

- `symbol`
- `dataSource`
- `startDate`，格式 `YYYY-MM-DD`
- `endDate`，格式 `YYYY-MM-DD`

后端校验日期格式、先后顺序和未来日期。Baostock 使用该区间查询日行情；东方财富新闻分页后按发布时间过滤该区间；三张财报保留公告日期不晚于结束日期的记录。接口返回实际请求区间和最新交易日。

`POST /api/analyze/start` 继续调用现有后端日期校验，作为并发和绕过前端情况下的最终保护。无效日期在创建任务记录和加入后台任务之前返回 HTTP 400。

## 数据合并

新抓取的行情和结果文件代表用户指定区间，覆盖对应股票原文件。新闻与已有文件合并去重，但保存后仅保留本次区间内新闻，确保分析窗口和用户选择一致。财报保存截止结束日期可见的全部历史报告，以支持趋势和同比分析，并避免使用结束日期之后才公告的数据。

财报以 `NOTICE_DATE` 为首选公开日期；缺失时使用 `REPORT_DATE`。只有公开日期不晚于结束日期的记录可写入。

## 错误处理

- 缺少日期或日期格式错误：返回 400 风格的可读错误。
- 开始日期晚于结束日期：拒绝请求。
- 结束日期晚于当天：拒绝请求。
- 区间内无行情：返回 `error`，不覆盖旧行情文件。
- 区间内无新闻：新闻模块返回 `error`，顶层状态为 `partial`。
- 截止结束日期无可用财报：对应财报模块返回 `error`。
- 分析日期不存在：前端只弹提醒；后端若被直接调用则返回 400，且任务列表中不产生运行任务。

## 测试

- 日期范围校验覆盖缺失、非法格式、倒序和未来日期。
- Baostock 和 Tushare 请求使用用户日期范围。
- 新闻过滤只保留区间内记录。
- 财报过滤以公告日期为准，不发生未来信息泄漏。
- 前端请求包含开始和结束日期。
- 无效分析日期在运行状态初始化前被拦截。
- 后端无效日期不会创建任务。
- 后端全套测试、前端专项测试和生产构建通过。

## 非目标

- 不允许选择未来日期。
- 不自动将无效分析日期静默替换为最近交易日。
- 不为停牌日或节假日伪造数据。
