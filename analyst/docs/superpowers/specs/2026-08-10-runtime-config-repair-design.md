# AnalystVerse 运行时配置修复设计

## 目标

第一阶段只修复系统配置，不改造模型线程和模块增量输出。修复后的配置需要满足：保存操作可靠、页面刷新后正确回显、下一次分析立即使用新配置，以及敏感凭据在服务重启后仍能安全恢复。

## 配置边界

后端以 `server_runtime_config.json` 作为唯一的可变运行时配置存储。模型配置、数据路径、数据源、抓取地址及敏感凭据都由统一配置服务读取和更新。`.env` 只作为部署时的初始值及加密主密钥来源，不再由 HTTP 接口修改。

运行时配置优先级固定为：单次分析请求中的显式覆盖值 > 已保存运行时配置 > 环境变量初始值 > 程序默认值。敏感字段不允许通过普通读取接口返回明文。

## 敏感凭据加密

敏感字段包括 DeepSeek API Key 和 Tushare Token。服务器通过环境变量 `CONFIG_ENCRYPTION_KEY` 接收任意非空字符串，并结合应用固定上下文和持久化随机盐，通过标准密钥派生函数生成 Fernet 加密密钥。随机盐与密文可以保存在运行时配置文件中，主密钥字符串不得落盘。

保存敏感字段时：

- 缺少 `CONFIG_ENCRYPTION_KEY` 时拒绝保存敏感字段，返回明确的配置错误；非敏感字段仍可保存。
- 新值为空或包含脱敏占位符时保留原值，防止页面刷新后误清空。
- 清除凭据必须使用显式的清除标记，不能依赖提交空字符串。
- 接口仅返回 `apiKeyConfigured`、`maskedApiKey`、`tushareTokenConfigured` 等状态字段。

当环境变量中的主密钥与已有密文不匹配时，服务不得静默覆盖密文；读取配置和启动分析时返回可诊断错误，提示恢复原密钥或显式重置凭据。

## 后端配置服务

重构 `services/runtime_config.py`，集中承担：

- 配置字段规范化、默认值合并和数值校验。
- 敏感字段加密、解密、脱敏及显式清除。
- 数据源配置与模型配置的统一读取和更新。
- 在进程锁内执行“写临时文件、刷新、原子替换”，避免并发写入产生半文件或损坏 JSON。
- 为每次分析生成不可变配置快照，保证一次分析过程中配置一致。

`config.py` 只消费配置服务提供的有效快照，不再自行实现一套不同的合并规则。现有 `/api/config/data-source` 可以保留兼容路由，但内部必须委托统一配置服务，不能写 `.env`。

## 前端行为

系统配置页加载时同时读取模型配置和数据源配置。保存后以后端返回的配置重新填充页面，不把“请求成功”误当成“配置已生效”。

模型和数据源表单都使用统一 API 封装：

- 密钥输入框永不填入真实值，只显示配置状态与脱敏提示。
- 未输入新密钥时保留服务器中的旧密钥。
- 提供单独的清除按钮，并在清除前确认。
- 保存失败时展示后端返回的具体原因。
- 分析请求不再从浏览器缓存附带旧配置覆盖服务器最新配置；仅在确有单次覆盖需求时传入明确字段。

## 即时生效与并发语义

更新成功后，下一次创建的分析任务读取最新配置快照，无需重启服务。已经运行中的分析继续使用启动时的快照，避免执行中途切换模型、路径或密钥。

运行时配置文件写入由同一把进程锁串行化。当前部署保持单 Uvicorn worker；未来若启用多进程，需要把存储升级为具备跨进程锁或事务的方案。

## 错误处理

配置接口使用明确的 4xx 响应区分字段校验失败、缺少主密钥、密文无法解密和不支持的数据源。文件系统写入失败返回服务端错误，并保留原配置文件。日志不得记录明文凭据或完整请求体。

## 验证

测试覆盖：

- 普通配置保存后刷新回显一致。
- API Key 和 Tushare Token 只以密文落盘，服务重载后可解密使用。
- 未提交新凭据时保留旧值，显式清除时才删除。
- 缺少或更换 `CONFIG_ENCRYPTION_KEY` 时产生明确错误且不破坏密文。
- 数据源兼容接口与统一接口读取同一状态。
- 保存后新分析使用最新配置，运行中的分析保持原快照。
- 多线程并发保存不会生成无效 JSON。
- 前端构建通过，后端配置与分析相关测试通过。

## 后续阶段接口预留

第二阶段的多线程改造只消费本阶段提供的不可变配置快照。第三阶段的模块完成即输出将通过任务事件流传递结果，不直接读写配置文件。本阶段不实现线程池、异步结果保存或增量输出。
