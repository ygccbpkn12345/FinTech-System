# 东方财富新闻与基本面爬虫设计

日期：2026-08-11

## 目标

扩展现有“爬虫抓取”流程：继续使用 Baostock 获取日行情，同时从东方财富公开数据接口获取个股新闻、资产负债表、利润表和现金流量表。抓取完成后，后端重新计算股票数据状态，前端据此同步更新智能分析可用状态。

## 范围

- 支持沪深 A 股六位股票代码。
- 新闻写入 `data/news/<symbol>.csv`。
- 三张财报分别写入：
  - `data/fundamentals/Balance Sheet/<symbol>.csv`
  - `data/fundamentals/Income Statement/<symbol>.csv`
  - `data/fundamentals/Cash Flow Statement/<symbol>.csv`
- 不修改分析器的工具调用接口和目录协议。
- 不实现网页 HTML 解析，不增加浏览器自动化。

## 架构

新增独立的东方财富抓取服务，避免继续扩大 `api_server.py` 中的接口处理函数。服务包含四类职责：

1. 将六位股票代码转换为东方财富接口需要的证券标识。
2. 使用 `httpx` 请求新闻与财务公开接口，处理分页、超时、HTTP 错误和无数据响应。
3. 将接口响应转换成分析器当前能够读取的 CSV 表结构。
4. 采用临时文件加原子替换方式写入目标文件，避免失败时破坏已有可用数据。

`/api/data/fetch` 作为协调层：先获取行情，再调用东方财富服务抓取四类数据，最后调用现有 `get_symbol_data_status` 获取真实落盘状态。

## 数据规则

### 新闻

- 抓取目标股票的最新新闻并支持分页。
- 输出至少包含 `Publish Time`、`Title`、`keyword`、`source`、`Content`。
- 发布时间规范为可被 Pandas 解析的日期时间。
- 按新闻唯一标识去重；接口无唯一标识时，以“发布时间 + 标题”去重。
- 与已有文件合并后去重并按时间排序，避免每次抓取覆盖历史记录。

### 基本面

- 分别请求资产负债表、利润表和现金流量表。
- 保留东方财富返回的完整字段，确保现有分析器能够读取报告期和财务指标。
- 报告期字段统一为现有 CSV 使用的统计截止日期列；保存所有可用报告期，而不是只保存最新一期。
- 按证券代码和报告期去重，优先保留更新时间较新的记录。
- 三张表必须分别成功落盘，基本面状态才为 ready。

## 执行与状态

抓取结果包含各模块明细：`market`、`news`、`balanceSheet`、`incomeStatement`、`cashFlowStatement`。每个模块报告状态、记录数和错误信息。

- 所有核心模块成功：顶层状态为 `ok`。
- 行情成功但新闻或财报部分失败：顶层状态为 `partial`，保留成功数据并返回失败模块。
- 行情失败：顶层状态为 `error`，不继续宣称该次抓取完成。

无论成功还是部分成功，接口都在返回前重新调用股票状态检查。前端收到结果后刷新数据状态；只有行情、新闻、三张财报及结果文件均存在时，智能分析才显示可分析。

## 错误处理

- 网络请求设置连接和读取超时，并对临时网络错误进行有限次数重试。
- 非 2xx、JSON 结构异常、接口业务错误和空数据分别转换为可读模块错误。
- 单个东方财富模块失败不阻止其他模块执行。
- 日志不输出 Token、Cookie 或完整响应正文。
- 旧文件只在新数据转换和校验成功后替换。

## 测试

按 TDD 实施，至少覆盖：

- 股票代码到东方财富证券标识的转换。
- 新闻分页、字段转换、合并和去重。
- 三张财报响应转换及报告期去重。
- 空字符串和空数值不会触发数值转换异常。
- 单模块失败返回 `partial`，其他成功文件仍保留。
- 全部完成后 `dataStatus.news` 和 `dataStatus.fundamentals` 为 ready。
- 现有后端测试、前端爬虫状态测试和生产构建继续通过。

## 非目标

- 不保证第三方公开接口永久稳定；接口变更通过模块化适配器和测试降低维护成本。
- 不抓取付费研报全文。
- 不扩展到港股、美股或基金。
