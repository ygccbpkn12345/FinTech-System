# AnalystVerse 多线程分析流水线设计

## 目标与范围

本阶段重构真实模型分析流水线的线程边界。五个分析师并行调用 LLM；五者全部结束后，router、manager、risk、final 和 reflection 在任务协调线程中严格串行执行。固定三个 I/O 工作线程异步保存结果、更新模块状态并产生完成事件。

本阶段建立模块事件能力，但前端逐模块展示属于下一阶段。本阶段不改变模型提示词、业务判断或最终结果结构。

## 执行拓扑

每个分析任务拥有一个协调线程。协调线程创建容量为五的分析师执行器，同时提交 market、news、fundamentals、industry 和 momentum 五个分析师节点。每个分析师允许独立并发调用 LLM。

协调线程等待五个分析师 future 全部完成并合并各自的状态增量。只有五个分析师均成功时才进入串行决策链：

`router → manager → risk_manager → final_decision → environment_simulation → reflector → 可选 weekly_reflector`

其中 environment simulation 不调用 LLM，但仍保持原有依赖顺序。串行链全部在协调线程运行，不交给 LangGraph 并行调度器。

## I/O 执行器

每个分析任务创建固定三个线程的 I/O 执行器。节点完成后，执行线程构造不可变模块快照并提交 I/O 工作：

- 原子保存该模块的结果文件。
- 更新任务内存中的模块完成状态。
- 写入模块完成事件，供下一阶段的增量 API 使用。

提交成功后模型线程立即继续，不等待单项保存。任务关闭提交入口后等待所有 I/O future 收口，保证最终完成响应对应的结果已经持久化。

待处理 I/O 工作使用容量为十二的有界队列。队列已满时提交线程等待可用槽位，避免磁盘持续故障造成无限内存增长。

## 状态合并

五个分析师从同一个只读初始状态快照开始，只能返回各自拥有的报告字段及必要消息。协调线程按固定分析师顺序合并结果，禁止多个分析师写同一业务字段。发生字段所有权冲突时任务失败，而不是以后完成者覆盖先完成者。

router 读取合并后的完整五分析师状态。后续节点每次接收前一节点产生的最新状态，并在协调线程中依序合并。

## 失败和取消

任一分析师失败时，协调器取消尚未开始的分析师 future；已经开始的外部 LLM 请求无法安全强制终止，需要等待返回。任务不进入 router，并记录失败的分析师名称和安全错误信息。

串行决策节点失败时停止后续模型节点，但仍等待已经提交的 I/O 工作结束。

I/O 失败不会中断正在进行的模型调用。每个 I/O future 保存模块名；任务收口时聚合失败。如果存在任何保存、状态更新或事件写入失败，任务最终标记失败，并报告具体模块，不返回虚假的 completed 状态。

所有执行器都在 `finally` 路径关闭。关闭时等待已开始工作，取消尚未执行且已无意义的工作。日志包含任务、模块、线程角色和耗时，但不得包含 API Key 或完整敏感请求。

## 现有 LangGraph 调整

移除 `Send` fan-out 对五分析师并发的隐式控制，改由明确的分析师执行器负责 fan-out/fan-in。这样可测试线程数量、异常传播和合并顺序。

现有分析师并发信号量及 `analystConcurrency` 运行逻辑被移除。固定并发数为五；系统配置页面删除该误导字段。LangGraph 可继续用于节点定义，或由一个轻量协调器直接调用节点函数，但不得再次并行调度串行决策链。

同一股票的现有任务锁继续保留，避免共享 Chroma 记忆目录并发读写。不同股票任务可以各自运行；服务器资源上限仍由部署层控制。

## 模块结果文件与事件边界

模块结果采用任务目录隔离，路径包含 task ID，避免同一股票不同日期的结果互相覆盖。文件写入使用临时文件加原子替换。事件记录至少包含递增序号、模块名、完成时间、模块状态和可公开结果；不得包含配置快照中的明文凭据。

下一阶段可以直接基于事件记录增加轮询或流式接口，而不需要再次侵入模型节点。

## 验证

自动测试覆盖：

- 五个分析师实际运行在五个工作线程，并允许执行时间重叠。
- router 只在五个分析师全部完成后开始。
- router、manager、risk、final、reflection 使用同一个协调线程且顺序固定。
- 分析师结果按字段所有权安全合并，完成先后不改变最终结构。
- 节点完成后 I/O 与后续模型执行重叠。
- I/O 执行器最多使用三个线程，任务完成前等待全部保存。
- 分析师、串行节点和 I/O 异常分别遵守定义的停止及收口语义。
- 旧 `analystConcurrency` 不再影响执行，也不再出现在系统配置页面。
- 既有配置测试、后端测试、Python 编译和前端生产构建继续通过。
