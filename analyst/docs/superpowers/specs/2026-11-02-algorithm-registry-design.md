# 算法注册与发现

目标：统一名称、描述、必填参数、执行及 ToolResult；提供 Python/HTTP 算法增删改查，新增算法无需修改聊天前端或编排主流程。

采用现有 ToolRegistry 扩展方案：AlgorithmManager 管理持久化定义和共享注册表；每轮聊天使用注册表快照。本地算法来自可信 services/tools/plugins 模块的 build_tool() 工厂，现有两个工具作为内置本地实现。HTTP URL 只从管理配置读取，模型参数不能改变 URL，GET 使用查询参数，POST 使用 JSON。

注册定义包含 name、description、required_parameters、kind，以及 python 的 local_tool 或 http 配置。name 创建后不变，更新使用完整定义。Python 定义不能移除实现必填参数。首次启动默认包含股票预测和爬虫，后续以持久化文件为准，包括空列表。写文件成功后才替换运行中注册表；单进程锁保护并发修改，文件原子替换。多进程同步不在本次范围。

算法管理页提供查询、类型筛选、新增、编辑、确认删除和错误反馈。后端提供 /api/algorithms 的列表、新增和单项查询、更新、删除；/api/algorithms/local-tools 列出可信本地实现。禁止通过 API 导入任意 Python 路径或上传代码。管理接口沿用现有部署信任边界，HTTP 地址由管理员配置。

聊天保留业务预测和数据更新行为，泛化缺参检查与多轮补参；注册表删除后等待会话返回可读错误。工具结果沿用现有通用卡片。

备选：只做内存注册无法重启恢复；数据库和插件上传平台超出当前单机部署需求。因此采用插件目录和 JSON 配置，保留未来替换存储接口的空间。

验证：真实文件持久化、CRUD/API 错误码、动态聊天路由、通用补参、删除等待工具、HTTP 固定 URL/GET 参数、现有后端和前端回归与构建。
